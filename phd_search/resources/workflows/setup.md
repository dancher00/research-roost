# /setup — researcher profile and search strategy

Run this workflow for initial setup or evidence-driven profile updates. The goal is a confirmed, reusable profile rather than a generic biography. Read `docs/data-model.md` and `docs/profile.md`.

1. Run `./roost doctor`; use `./roost init` if the selected workspace is missing. Preserve existing data. Keep candidate information under the ignored workspace, not AGENTS.md, CLAUDE.md or tracked examples. Read the existing profile and document metadata once.
2. Offer the applicable intake path: registered documents, a pasted CV/profile, or a concise interview. Documents can be registered with `./roost profile document --file PATH --category cv` and the corresponding categories for transcripts, publications, portfolios, language tests and reference material. Preserve originals and extraction limitations; scanned PDFs require a user-reviewed transcription/OCR. Do not upload personal documents to external services merely to parse them.
3. Establish research interests in the user's own terms. Ask about questions, subject areas, theoretical/empirical/practice approaches, methods, outputs and intellectual motivation. Do not impose STEM vocabulary, publication counts or experimental research. A portfolio, critical edition, clinical practice, archive, composition or professional project may be relevant evidence.
4. Record identity/contact details only as provided. Record education with exact degree names, institution, dates, grading scale, completion status and source. Do not convert GPA or assert degree equivalence without an official rule. Distinguish awarded and expected qualifications, authorship, individual contribution and publication status.
5. Capture languages and dated tests, skills with concrete evidence, research/practice experience and factual accomplishments. For every reusable claim add a confirmed `facts` entry with id, claim and source. Unconfirmed inferences stay in notes until the user confirms them. Never claim a user read a paper because it appears in their publication list or the agent read it.
6. Establish preferences: target and excluded countries, opportunity types, start window, funding/tuition needs, realistic budget constraints, mobility/relocation constraints, document language, supervisor contact preferences and deal-breakers. ResearchRoost supports PhD, research internships and summer/winter/research/training/field schools and short courses; read `docs/opportunities.md`. Save selected types in `preferences.opportunity_types`. An empty legacy selection retains PhD discovery; do not silently enrol the user in all modes. Leave uncertain preferences empty/null. Citizenship and residence/activity history are optional sensitive eligibility facts: ask only when an actual opportunity's rule requires them.
7. Ask only for information that cannot be inferred from supplied documents, grouped into a manageable batch. Continue document inventory and structural preparation while waiting. If preferences are undecided, keep the tool universal rather than choosing a field/country for the user.
8. Update `profile.json` with exact supported facts and source paths. `./roost profile import --file PATH` validates and backs up the previous profile. `./roost profile fact --claim TEXT --source SOURCE` records a new user-confirmed claim. Correct conflicting profile facts rather than adding a contradictory duplicate. Changing the profile deliberately invalidates earlier assessments; do not hide that.
9. For internships and schools, record confirmed availability windows, actual enrollment status and its dates, return-to-study requirements, work permission and home-institution approval only when supported. Expected graduation does not establish enrollment through an internship's end; a current PhD neither automatically qualifies nor excludes a school applicant. Run `./roost profile validate`, then `./roost search-plan` or `./roost search-plan --family internship|school|phd|all`. An explicit family explores that mode without changing saved preferences. Review topic synonyms and translations with the user; configure official institutional sources and useful feeds. Plans are queries, not found opportunities.
10. Present the resulting profile, essential remaining unknowns, search strategy and files. A complete profile does not require optional publications, tests, awards, behavioural assessments, nationality or funding preferences. Report what is confirmed and what still limits eligibility checks.

Do not automatically subscribe the user to alerts, install global plugins, contact institutions or publish a profile. Those actions need the corresponding user request.
