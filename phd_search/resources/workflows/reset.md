# /reset — reversible local archive/reset

1. Identify the user's intended scope: profile only, search/application state while retaining profile/documents/source/template configuration, or all local state. Do not infer a destructive scope from a request to fix one field.
2. Run `./roost reset --scope profile|state|all` without `--execute` to prepare the exact plan. It performs no reset. Inspect the workspace and archive destination. If there is any ambiguity, show the concrete plan and ask for the missing scope; existing explicit reset authorisation need not be requested again.
3. `--execute` on profile scope backs up the current profile before replacing it with the blank schema. State/all scopes rename the entire workspace to a sibling timestamped archive and create a new workspace. State scope then retains the profile, documents, sources and templates. Nothing is deleted from the archive.
4. Verify the new workspace with `./roost doctor` and confirm that the archive exists. Init/reset place a local private ignore marker in the workspace before it is archived; the repository also excludes default workspace-archived paths. Ignore rules do not untrack previously committed files. Keep user-selected backups/exports outside public source trees. Do not modify the reference repositories in help, other workspaces, credentials, external accounts, schedules or connector data as part of a local reset.
5. For portable backups use `./roost backup --out PATH_OUTSIDE_WORKSPACE.zip`; restore with `./roost restore --file BACKUP.zip --to NEW_DIRECTORY`. Restore validates manifest digests, paths and database integrity. Preserve personal backups privately.
