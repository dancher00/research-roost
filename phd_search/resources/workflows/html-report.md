# /html-report — offline dashboard, tracker and calendar

1. Read current local state; do not infer a submission or outcome from a generated document. Run `./roost report`, `./roost export csv`, `./roost export calendar`, and `./roost export json` when requested. Use `--out PATH` for a selected destination.
2. The HTML report is a standalone file with embedded styling/filtering, no external libraries, tracking, fonts or network requests. It shows opportunity/application counts, stages, countries, funding, evidence coverage, assessment state and recent events. Use `--family phd|internship|school` for a focused report. Keep family/rubric comparison groups distinct; different rubric scores are not one scientific league table. Unknown and stale results remain explicit.
3. Inspect counts and a few representative rows against the database. A submitted-history count differs from current submitted-status count; an interview count comes from recorded interview transitions. Multiple application variants can create several rows for one opportunity. Do not call these causal success rates.
4. CSV is intended for spreadsheets and neutralises formula-prefixed cells. JSON retains structured local metadata. Calendar exports named application, scholarship, registration, acceptance and reference deadlines as distinct events, alongside scheduled interviews/assessments and pending reference dates. Event attendance dates are not application cutoffs. Date-only deadlines remain all-day and timezone-aware cutoffs remain exact times; inspect the exported named entries against the source.
5. Deliver clickable local artifacts. A local report can contain personal application metadata; do not publish/host/share it unless explicitly requested. Optional external Notion publication is a different authorised workflow.
