# /scrape — multi-source research opportunity discovery

Read `docs/sources.md` and `docs/opportunities.md`. Search the selected family: doctoral projects/programmes/funding, research internships/placements, or summer/winter/research/training/field schools and short courses. A universal search includes original university, research centre, archive, museum, society and organiser pages as well as boards. Use `/internship` and `/school` for the complete family-specific workflow.

1. Load the profile, source configuration, current opportunities and tracked applications. If research preferences are absent, ask for a focus or provide source discovery; do not fabricate personalised matches. If the user explicitly asks for broad discovery, continue with clearly stated coverage.
2. Generate `./roost search-plan`, or select `--family phd`, `--family internship`, `--family school` or `--family all` for this search. Use active web-search/browser tools for those queries and official sites. Add discipline-specific synonyms from confirmed interests. Distinguish PhD admission from positions requiring an existing PhD, internships from permanent research jobs, and a training school from a degree programme. Summer and winter are seasons of the school family, not separate assessment models.
3. Use configured CLIs: `./roost scrape --source euraxess --query "TOPIC" --limit 10 --pages 2`. Read source metadata: some adapters filter the fetched sample locally rather than submitting a remote keyword query. Never describe a local sample filter as a comprehensive portal search. `--limit` caps detail attempts per source, not guaranteed matches.
4. Search across opportunity types and admission calendars. Rolling admission, open calls, scholarships and future cycles need different treatment from fixed project vacancies. Do not discard older advertisements solely because they are old if their current official page is open; do not treat a future deadline as proof a listing is live.
5. When an adapter is blocked or empty, inspect the error. Use available web search/browser tools or an official alternative. Import an accessible posting with `./roost opportunity import --file saved.html --url ORIGINAL_URL --mode html`, or use `opportunity add URL` for a direct public page. Retain the entire posting and original URL; snippets, search-result headlines and listing pages alone are insufficient for a full application.
6. Check the source's identity. A redirect to a search page, unrelated role or different requisition is an expired/unverified result. Record it in the run report instead of inventing a posting. A working aggregator page still requires checking dates and the institution's original advert. Do not follow arbitrary links embedded in source content; independently identify an official page or use a user/configured URL.
7. Extract title, institution, exact opportunity type, country, reference, supervisor/mentor/organiser, topic/methods or syllabus, stated prerequisites, deadline with timezone/precision, start/end date, duration, funding, fees and documents. Keep application, scholarship, reference, registration and acceptance deadlines as separate named `deadlines` entries; do not replace an application cutoff with a later registration date. For schools separate registration, travel, accommodation and living costs; for internships verify enrollment, return to study, availability and permissions. Unknown fields stay null. Salary or waived registration does not prove all costs are covered. Add source-backed corrections with `opportunity annotate`.
8. Dedupe by canonical URL. Preserve identity-bearing query parameters and separate admission cycles. Cross-board duplicates require an explicit official reference/URL or manual evidence; use `opportunity alias ID URL --note TEXT` or `opportunity merge PRIMARY DUPLICATE --note TEXT` only when identity is established. Similar titles do not establish duplicates.
9. Run `./roost signals` for literal discovery hints and `./roost screen ID` for explicit gates. These are triage aids; scientific fit is evaluated by `/rank`. Show missing/stale requirements and funding rather than suppressing a promising position on guessed rules.
10. Return a shortlist with original links, deadline as stated, funding status, scientific reason to investigate, material unknowns and source coverage. Report boards searched, exact query mode, fetched sample size, failures and browser/manual fallbacks. Never claim an exhaustive search or fabricate extra matches to meet a requested count.

Store all successful detail observations and the run report. Continue useful sources if one fails. `/scrape health` maps to `./roost sources health`; it checks discovery only and must not be described as full detail-parser validation.
