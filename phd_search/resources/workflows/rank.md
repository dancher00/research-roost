# /rank — research/training fit and eligibility

Read `docs/rubric.md`, `docs/opportunities.md` and `docs/data-model.md`. Research and training judgment belongs to the agent/human. CLI keyword signals never become a substantive score automatically. Identify the opportunity family before assessment.

1. Load the candidate profile once, unassessed/stale opportunities and their complete cleaned evidence. Exclude only confirmed vetoes or user-dismissed opportunities; keep material unknowns visible. Refresh a source when current availability, a deadline or changed eligibility matters. A cached HTTP 304 is revalidation; a saved file import has a different provenance.
2. Establish the actual question/project, programme route, prerequisites, methodological demands, supervisory environment and funding conditions. Verify institution/supervisor facts and cited work from independent primary sources. Record external supporting excerpts in a dossier so their exact files and digests can support the assessment.
3. Record normalized metadata with a source quote and current evidence digest using `opportunity annotate`. Set `requirements.reviewed` true only after checking the complete requirements. The institution's absence of a requirement is not a claim that a candidate meets an unstated rule.
4. Run `./roost screen ID`. Gates include deadline, configured geography and opportunity type, confirmed funding/tuition requirements, comparable minimum funding, degrees, language tests/levels, citizenship, start date and explicitly recorded extra constraints. Mobility and degree equivalence require the exact current sourced rule; nationality alone does not establish mobility eligibility. Refer unresolved interpretations to the institution rather than manufacturing a verdict.
5. Generate `./roost assessment packet ID`. Follow its bound, versioned family rubric on a 0–5 scale. PhD dimensions are research_fit, methods, supervisor_fit, preparedness, funding, environment. Internship dimensions are project_fit, methods, mentor_fit, preparedness, funding, environment. School dimensions are learning_fit, prerequisites, programme_fit, funding, practical_fit. Use packet weights and `docs/rubric.md`; never score a school as a doctoral project or force a named PI on it. Use null when evidence is inadequate, including mentoring quality. Humanities, theoretical and practice work are judged by their actual methods, not missing STEM requirements.
6. For each scored dimension provide a reason, exact posting quotations and relevant profile JSON pointers. Research/methods/preparation require profile evidence. External evidence needs its archived local file, SHA-256, exact quote and original URL. Distinguish demonstrated skills, reasonable adjacency and a training gap. No invented reading, scholarship promises, institutional prestige proxy or personality inference.
7. Name 1–3 concrete strengths, gaps and questions. State whether to prioritise, investigate, defer or dismiss and why. Check scientific claims against source evidence in a distinct critical pass. If the same agent does both phases, disclose that; do not describe it as independent review.
8. Import the completed assessment with `./roost assessment import ID --file PATH`. The validator rejects stale bindings, unsupported excerpts, missing candidate references and invalid scores. Run `./roost rank`; use `--include-failed` to audit confirmed vetoes.
9. Present family/rubric, score, coverage and the full unknown interval. A 30%-covered assessment with interval 24–94 is not a 24/100 rejection or a 94/100 match. A point score is returned only at full coverage. Compare scores only within the same `comparison_group`; a school 85 is not better than a PhD 80. A combined report must separate family rankings and explain timing/goal trade-offs in prose. Scores never represent admission probability or universal scientific merit.
10. Offer the highest-value next action: verify funding/eligibility, research a group, ask a targeted question, or draft a specific application. Proceed when the user's existing request authorises it; do not add repetitive permission checkpoints.
