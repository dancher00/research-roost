# /add-template — custom academic document layout

1. Establish the document kind, institutional prompt, language/script, required format, source template and actual page/word constraints. Content and layout are separate: registering a template does not authorise stronger claims or a different programme prompt.
2. Inspect the supplied source and licence. The CLI renderer accepts a self-contained UTF-8 LaTeX wrapper with exactly one `{{BODY}}` placeholder and xelatex, lualatex or tectonic. Required fonts must be installed or supplied explicitly. Do not execute template-supplied shell commands or install unrelated toolchains automatically.
3. Prepare the layout using the user's template, keeping editable source. Register with `./roost template add ID --file template.tex --engine tectonic` (or an available engine). Registration performs a real Unicode-containing test compile in a temporary directory and records the source digest; absent/failed compilers leave the template unregistered.
4. Render the actual packet with `application render APP_ID --template ID --pdf`. Check every final PDF visually and inspect extractable text, contacts, reading order, glyph coverage, headings/page breaks and institutional page limits. The test compile does not establish final-document quality.
5. Update `requirements.json` with sourced length/format rules and refresh the review hashes after final rendering. Never mark visual verification complete without inspecting the rendered pages. If compilation is unavailable, deliver editable LaTeX/HTML with the missing check explicit rather than silently substituting a verified PDF.
6. Other authoring formats (Word/Typst/design templates) may be handled by the active agent with their actual toolchain and the same evidence/review rules, but must be labelled as externally authored artifacts; the CLI does not claim native support for unimplemented template engines.
