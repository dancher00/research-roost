# /add-portal — add a public academic source

Read `docs/sources.md`. Build from the source's actual interface rather than guessing API endpoints, filters or selectors. Supported registry adapters: HTML link discovery + detail extraction, RSS/Atom, JSON with explicit field paths, and browser-only discovery handoffs.

1. Establish source URL, scope/discipline/geography, language, a realistic test query and whether the user wants scheduled or one-off use. Do not assume every university uses the same ATS or every board exposes a feed.
2. Inspect official search/feed documentation, robots, public HTML/JSON response and one actual detail page. Identify authentication requirements, pagination, identity/reference, title, institution, dates, funding/fees and the original institution link. Record which filters work remotely and which need local filtering. Do not bypass a login, CAPTCHA, disallowed route or rate limit by silently changing transport.
3. Prefer a documented public feed/API. For HTML, choose a narrow `link_pattern` for actual posting URLs; test that it excludes search/profile/navigation/expired redirects. Generic HTML detail extraction uses JobPosting JSON-LD or cleaned visible text, with unknown metadata left for source-backed annotation.
4. Prepare a source JSON object with a unique lowercase id, name, kind, enabled flag, verified URL/template, exact link pattern or JSON item/url/title paths, verification date and honest notes. `{query}` and `{page}` substitutions are explicit; do not add them unless the parameter was actually tested. For blocked/unsupported interfaces use `kind: discovery` and a search/browser handoff rather than claiming a working adapter.
5. Test a small live listing and a single actual detail using a separate sample workspace. Confirm original identity, title, extraction, dates and error paths. Add meaningful local fixtures for a new parser/transport boundary; fixture success alone does not prove live compatibility.
6. Register with `./roost sources add --file source.json`, then probe `./roost sources health --source ID`. State whether only discovery or also detail ingestion passed. A source can be disabled with `sources toggle ID --enabled false`; keep it for future repair.
7. Record selectors/interface quirks and limits in `docs/sources.md` or a source-specific note. Continue the original search using supported sources. Future runs discover registry entries automatically; no hardcoded source list in orchestration needs editing.
